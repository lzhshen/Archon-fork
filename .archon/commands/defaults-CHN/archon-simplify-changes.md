# 简化变更代码

---

## 重要提示：输出行为

**你的输出将作为 GitHub 评论发布。** 请将工作输出保持在最低限度：
- 不要叙述每个步骤
- 不要输出冗长的进度更新
- 仅在最后输出结构化的报告

---

## 任务目标

审查本分支上所有已变更的代码，并直接实施简化。你不是顾问角色 -- 你需要编辑文件、验证、提交并推送。

## 范围

**仅限本 PR 中变更的代码** -- 运行 `git diff $BASE_BRANCH...HEAD --name-only` 获取文件列表。不要触碰不相关的文件。

## 简化内容

| 优化方向 | 关注要点 |
|---------|----------|
| **不必要的复杂性** | 深层嵌套、混乱的逻辑路径 |
| **冗余代码** | 重复逻辑、未使用的变量/导入 |
| **过度抽象** | 让代码更难理解而非更清晰的抽象 |
| **命名不当** | 不清晰的变量/函数名 |
| **嵌套三元表达式** | 三元链中的多重条件 -- 应使用 if/else |
| **过于紧凑的单行代码** | 牺牲可读性的精简代码 |
| **显而易见的注释** | 描述了代码本身已经清楚表达的内容的注释 |
| **不一致的模式** | 未遵循项目约定的代码（阅读 CLAUDE.md） |

## 规则

- **保持功能完全不变** -- 简化不得改变行为
- **清晰优于简洁** -- 可读性优先于紧凑性
- **不做推测性重构** -- 仅简化明显可改进的部分
- **遵循项目约定** -- 在修改前阅读 CLAUDE.md
- **小而明确的改动** -- 每项简化都应该是显而易见正确的

## 流程

### 阶段一：分析

1. 阅读 CLAUDE.md 了解项目约定
2. 获取变更文件列表：`git diff $BASE_BRANCH...HEAD --name-only`
3. 阅读每个变更文件
4. 识别每个文件中的简化机会

### 阶段二：实施

对每项简化：
1. 编辑文件
2. 运行 `bun run type-check` -- 如果失败，回滚该改动
3. 运行 `bun run lint` -- 如果失败，修复或回滚

**记录你编辑过的每个文件路径。** 你在阶段三需要此列表，以便仅暂存你修改过的文件。

### 阶段三：验证与提交

1. 运行完整验证：`bun run type-check && bun run lint`
2. 如果应用了简化，**仅**暂存你在阶段二中编辑的文件 -- 不要使用 `git add -A`、`git add .` 或 `git add -u`：
   ```bash
   # 按名称暂存，使用你在阶段二中记录的列表
   git add path/to/file1.ts path/to/file2.ts
   # 确认没有其他文件混入
   git status --porcelain
   ```
3. **绝暂存**报告、临时文件或 PR 正文等产物，即使它们在工作树中显示为未跟踪或已修改：
   - `$ARTIFACTS_DIR` 下的任何内容（产物目录通常位于工作树之外，但可能存在副本/符号链接）
   - 仓库根目录下的 `review/`、`simplify-report.md`、`*-report.md`
   - `.pr-body.md`、`pr-body.md`、`*.scratch.md`、`*.tmp.md`
   - 如果 `git status --porcelain` 显示你无法确认为简化改动的文件，请保持它们未暂存
4. 仅提交并推送已暂存的源码编辑：
   ```bash
   git commit -m "simplify: reduce complexity in changed files"
   git push
   ```
5. 如果没有应用任何简化，完全跳过提交

### 阶段四：报告

将报告写入 `$ARTIFACTS_DIR/review/simplify-report.md` 并输出：

```markdown
## 代码简化报告

### 已执行的变更

#### 1. [简要标题]
**文件**：`path/to/file.ts:45-60`
**类型**：减少嵌套 / 改善命名 / 移除冗余 / 等
**修改前**：[代码片段]
**修改后**：[代码片段]

---

### 汇总

| 指标 | 数值 |
|------|------|
| 分析文件数 | X |
| 已应用简化数 | Y |
| 净行数变化 | -N 行 |
| 验证结果 | 通过 / 失败 |

### 无需变更
（如果没有需要简化的内容，请说明 -- "代码已经很整洁。未应用任何简化。"）
```
