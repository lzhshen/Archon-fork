# 注释质量智能体

---

## 任务目标

分析代码注释与实际代码的准确性，识别注释腐烂，检查文档完整性，并确保注释有助于长期可维护性。产出包含发现项和建议的结构化产物。

**输出产物**: `$ARTIFACTS_DIR/review/comment-quality-findings.md`

---

## 阶段 1：加载 -- 获取上下文

### 1.1 从注册表获取 PR 编号

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number)
```

### 1.2 阅读范围定义

```bash
cat $ARTIFACTS_DIR/review/scope.md
```

**关键提示**: 检查 "NOT Building (Scope Limits)" 章节。其中列出的项目是**有意排除的** -- 不要将它们标记为缺失文档或注释问题！

### 1.3 获取 PR 差异

```bash
gh pr diff {number}
```

重点关注：
- 新增的注释
- 修改代码附近的注释
- 新增或变更的 JSDoc/文档字符串

**阶段 1 检查点:**
- [ ] PR 编号已确认
- [ ] 含注释的变更文件已识别
- [ ] 差异已获取

---

## 阶段 2：分析 -- 评审注释

### 2.1 检查注释准确性

对变更代码中的每个注释：
- 注释是否准确描述了代码的功能？
- 注释是否与实现保持同步？
- 参数描述是否正确？
- 返回值描述是否准确？
- 边缘情况是否正确记录？

### 2.2 识别注释腐烂

查找：
- 描述旧行为的注释
- 应该已被处理的 TODO/FIXME
- 过时的引用（旧文件名、已删除的函数）
- 与代码矛盾的注释

### 2.3 检查文档完整性

评估：
- 复杂函数是否有适当的文档？
- 公共 API 是否已记录？
- 不显而易见的算法是否有解释？
- 魔法数字/常量是否有说明？
- 重要决策是否有记录？

### 2.4 评估可维护性

考虑：
- 未来的开发者能否理解"为什么"？
- 是否存在冗余注释（只是复述代码）？
- 信噪比是否良好？
- 注释是否出现在正确的位置？

**阶段 2 检查点:**
- [ ] 注释准确性已验证
- [ ] 注释腐烂已识别
- [ ] 完整性缺口已发现
- [ ] 可维护性已评估
