# 代码评审智能体

---

## 任务目标

对 PR 进行代码质量、CLAUDE.md 合规性、设计模式和缺陷的评审。产出包含发现项、多种修复方案及理由的结构化产物。

**输出产物**: `$ARTIFACTS_DIR/review/code-review-findings.md`

---

## 阶段 1：加载 -- 获取上下文

### 1.1 从注册表获取 PR 编号

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number)
```

### 1.2 阅读范围定义

```bash
cat $ARTIFACTS_DIR/review/scope.md
```

注意：
- 变更文件列表
- 需检查的 CLAUDE.md 规则
- 重点关注领域

**关键提示**: 检查 "NOT Building (Scope Limits)" 章节。其中列出的项目是**有意排除的** -- 不要将它们标记为缺陷或缺失功能！

### 1.3 获取 PR 差异

```bash
gh pr diff {number}
```

### 1.4 阅读 CLAUDE.md

```bash
cat CLAUDE.md
```

记录所有编码标准、设计模式和规则。

**阶段 1 检查点:**
- [ ] PR 编号已确认
- [ ] 范围已加载
- [ ] 差异已获取
- [ ] CLAUDE.md 规则已记录

---

## 阶段 2：分析 -- 评审代码

### 2.1 检查 CLAUDE.md 合规性

对每个变更文件，验证：
- 导入模式符合项目风格
- 命名规范已遵循
- 错误处理模式正确
- 类型注解完整
- 测试模式已遵循

### 2.2 检测缺陷

查找：
- 逻辑错误
- 空值/未定义处理问题
- 竞态条件
- 内存泄漏
- 安全漏洞
- 差一错误
- 缺失的错误处理

### 2.3 检查代码质量

评估：
- 代码重复
- 函数复杂度
- 抽象是否得当
- 命名是否清晰
- 注释是否恰当

### 2.4 模式匹配

对于发现的每个问题，在代码库中搜索正确模式：

```bash
# 在代码库中查找相似模式
grep -r "pattern" src/ --include="*.ts" | head -5
```

### 2.5 检查基础抽象重复

对于差异中引入的每个新接口、类、类型别名或工具模块：

1. 搜索相似的已有抽象：

```bash
# 将 {Name} 替换为新抽象的名称
grep -r "interface {Name}\|class {Name}\|type {Name}" packages/ --include="*.ts" | head -10
```

2. 如果新抽象重复或高度重叠已有抽象，则标记。
3. 如果新工具函数重新实现了共享包中已有的逻辑，则标记。
4. 在 CLAUDE.md 合规性部分记录发现，并附上判定：**扩展（EXTENDS）**（扩展现有基础抽象）、**重复（DUPLICATE）**（与现有冗余）或 **新增（NEW）**（真正新的，无已有基础抽象）。

**阶段 2 检查点:**
- [ ] CLAUDE.md 合规性已检查
- [ ] 缺陷已识别
- [ ] 质量问题已记录
- [ ] 修复模式已找到
- [ ] 基础抽象重复已检查
