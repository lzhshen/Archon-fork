# Ralph PRD 生成器

**输入**: $ARGUMENTS

---

## 你的角色

你正在为 Ralph 自主循环创建 PRD。你需要生成两个文件：
1. `prd.md` — 完整上下文文档（目标、用户画像、UX、成功标准）
2. `prd.json` — 用户故事跟踪（通过/未通过状态）

每次 Ralph 迭代会接收完整的 prd.md 上下文以及 prd.json 中对应的特定故事。

**关键规则：**
- 每个故事必须能在一次迭代内完成
- 故事按依赖关系排序（schema → 后端 → UI）
- 验收标准必须是可验证的（不能模糊）

---

## 阶段 1：启动

**若无输入**，询问：

> **你想要构建什么？**
> 用几句话描述功能或能力。

**若有输入**，确认：

> 我理解你想要构建：{复述你的理解}
> 是否正确？

**门控**：等待确认。

---

## 阶段 2：基础信息

同时提出以下问题：

> **基础问题：**
>
> 1. **问题**：这解决什么痛点？如果不构建会怎样？
>
> 2. **用户**：这是为谁设计的？描述他们的角色和背景。
>
> 3. **目标**：如果成功，理想的成果是什么？
>
> 4. **范围**：MVP 还是完整实现？哪些明确不在范围内？
>
> 5. **成功标准**：如何衡量这是否成功？哪些指标重要？

**门控**：等待回答。

---

## 阶段 3：UX 与设计

询问：

> **UX 问题：**
>
> 1. **用户旅程**：什么触发用户需要此功能？正常路径是什么？
>
> 2. **UI 需求**：有具体的视觉要求吗？颜色、位置、组件？
>
> 3. **交互模式**：用户如何交互？点击、键盘、API？
>
> 4. **边界情况**：需要处理哪些错误状态？空状态？
>
> 5. **可访问性**：有无 a11y 要求？

**门控**：等待回答。

---

## 阶段 4：技术基础

**使用 Explore 智能体：**

```
探索代码库中与以下功能相关的模式：{功能}

查找：
1. 可参考的相似实现（附带 file:line 引用）
2. 需扩展的已有类型/接口
3. 需遵循的组件模式
4. 使用的测试模式
5. 数据库 schema 模式
```

**总结：**

> **技术上下文：**
> - 相似模式：{file:lines}
> - 需扩展的类型：{types}
> - 需使用的组件：{components}
> - 测试模式：{pattern}
>
> 是否有额外的技术约束？

**门控**：短暂等待输入。

## 阶段 5：故事拆分

询问：

> **故事规划：**
>
> 1. **数据库**：需要哪些 schema 变更？新表/列？
>
> 2. **类型**：新接口或类型扩展？
>
> 3. **后端**：服务器逻辑、API 端点、服务？
>
> 4. **UI 组件**：新组件或修改？
>
> 5. **集成**：各部分如何连接？

**首先**，为此功能创建 ralph 目录：
```bash

### 故事规模规则

**合适的规模（一次迭代）：**
- 添加数据库列 + 迁移
- 创建一个工具函数 + 测试
- 添加一个 UI 组件
- 更新一个 API 端点

**过大（需拆分）：**
- "构建整个功能" → schema、类型、后端、UI
- "添加认证" → schema、中间件、登录 UI

### 验收标准规则

**好的标准（可验证）：**
- "添加 `priority` 列，类型为 'high' | 'medium' | 'low'"
- "当输入为 null 时，函数返回空数组"
- "按钮在提交时显示加载状态"

**差的标准（模糊）：**
- "能正确工作"
- "用户体验好"
- "处理边界情况"

每次 Ralph 迭代接收：

```bash

# 运行 Ralph — 指定功能目录
@Archon run ralph .archon/ralph/{feature-slug}

## 提问流程

```
启动 → 基础信息 → UX/设计 → 技术基础 → 故事拆分 → 生成文件
  ↓        ↓          ↓         ↓          ↓         ↓
 确认    问题、      旅程、    模式、     故事、    prd.md +
 创意    用户、      UI 需求、 类型、    数据库/   prd.json
         目标        状态      测试      API/UI 拆分
```

## 成功标准

- **上下文完整**：prd.md 包含目标、用户画像、UX、技术上下文
- **故事规模合理**：每个故事可在一次迭代内完成
- **依赖有效**：低优先级不依赖高优先级
- **标准可验证**：所有验收标准都可通过/失败来判定
- **可立即执行**：用户可以立即启动 Ralph 循环
