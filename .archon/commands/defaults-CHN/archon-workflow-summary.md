# 工作流摘要

**工作流 ID**：$WORKFLOW_ID

---

## 任务目标

为工作流运行创建最终摘要报告：
1. 概述实际实现内容与计划的对比
2. 列出偏差及其理由
3. 汇总未修复的审查发现（MEDIUM/LOW）
4. 创建可操作的后续建议
5. 在 GitHub PR 上发布评论
6. 写入产物以备后续参考

**输出**：用户可快速行动的决策矩阵。

---

## 阶段 1：加载 - 收集所有产物

**关键**：读取本次工作流运行的每一份产物，不可遗漏。

### 1.1 扫描工作流产物目录

```bash
# 列出本次工作流运行的所有产物
ls -la $ARTIFACTS_DIR/

# 逐一读取
for file in $ARTIFACTS_DIR/*.md; do
  echo "=== $file ==="
  cat "$file"
done
```

**预期产物**：
- `plan-context.md` - 计划摘要、范围限制、验收标准
- `plan-confirmation.md` - 模式验证结果
- `implementation.md` - 已完成任务、偏差、遇到的问题
- `validation.md` - 测试/代码检查/构建结果
- `pr-ready.md` - PR 编号、URL、最终提交
- `.pr-number` - PR 编号记录文件
- `.pr-url` - PR URL 记录文件

### 1.2 扫描审查产物

```bash
# 读取工作流作用域目录中的审查产物
ls -la $ARTIFACTS_DIR/review/

# 读取每份审查发现
for file in $ARTIFACTS_DIR/review/*.md; do
  echo "=== $file ==="
  cat "$file"
done
```

**预期审查产物**（位于 `runs/$WORKFLOW_ID/review/`）：
- `scope.md` - 变更文件、范围限制、重点关注区域
- `code-review-findings.md` - 代码质量问题
- `error-handling-findings.md` - 静默失败、catch 块问题
- `test-coverage-findings.md` - 测试覆盖空白
- `comment-quality-findings.md` - 文档注释问题
- `docs-impact-findings.md` - 文档更新需求
- `consolidated-review.md` - 综合发现及优先级
- `fix-report.md` - 已修复内容
- `sync-report.md` - 变基/同步状态（如适用）

### 1.3 提取关键数据

**从 plan-context.md**：
- 计划标题和摘要
- 预期变更的文件
- **不在范围内（Scope Limits）** - 关键：这些是后续跟进的候选项
- 验收标准

**从 implementation.md**：
- 已完成与计划中的任务对比
- 实际变更的文件
- **与计划的偏差** - 重点记录
- 实现过程中遇到的问题

**从所有审查发现**：
- CRITICAL/HIGH 级别问题（应该已修复）
- **MEDIUM 级别问题** - 后续跟进候选项
- **LOW 级别问题** - 可选后续跟进
- 按类别的具体建议

**从 fix-report.md**：
- 实际修复了什么
- 未修复什么（及原因）

### 1.4 交叉对比

跨产物进行对比：
- 计划 vs 实现：哪些一致？哪些偏离？
- 审查发现 vs 修复报告：哪些仍未解决？
- 不在范围内 vs 审查发现：审查者是否标记了排除项？（这是预期行为，需标注）

**阶段 1 检查点：**

- [ ] 所有工作流产物已读取
- [ ] 所有审查产物已读取
- [ ] 偏差已提取
- [ ] 未修复问题已识别
- [ ] 不在范围内的项目已记录

## 阶段 5.5：归档 - 创建向后兼容的符号链接

### 5.5.1 创建符号链接以支持基于 PR 的查找

创建符号链接以保持与基于 PR 的产物查找的向后兼容性：

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number 2>/dev/null)
if [ -n "$PR_NUMBER" ]; then
  mkdir -p $ARTIFACTS_DIR/../reviews
  ln -sfn ../runs/$WORKFLOW_ID/review $ARTIFACTS_DIR/../reviews/pr-$PR_NUMBER
fi
```

这使得旧版工具可以在 `$ARTIFACTS_DIR/../reviews/pr-{number}/` 路径下找到审查产物。
