# 代码审查：功能分支（PR 后状态）

分析 PR 中的代码变更，验证修复是否正确、完整，并以最佳方式实现。

---

## 阶段 1：加载上下文

### 1.1 读取 PR 详情和主分支分析

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number | tr -d '\n')
gh pr view "$PR_NUMBER" --json title,body,headRefName,baseRefName,labels
```

```bash
# 读取主分支分析（保证可用——本节点依赖于 code-review-main）
cat $ARTIFACTS_DIR/code-review-main.md
```

### 1.2 读取路径信息

```bash
cat $ARTIFACTS_DIR/.worktree-path
cat $ARTIFACTS_DIR/.feature-branch
```

---

## 阶段 2：分析差异

### 2.1 获取完整差异

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number | tr -d '\n')
gh pr diff "$PR_NUMBER"
```

### 2.2 读取功能分支上的变更文件

当前工作目录即为功能分支（工作树）。读取每个变更文件：

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number | tr -d '\n')
# 列出变更文件
gh pr view "$PR_NUMBER" --json files -q '.files[].path'
```

对每个文件，在当前工作目录中读取完整文件，以理解完整上下文，而不仅仅是差异片段。

### 2.3 深入分析每项变更

对每个变更文件：

1. **读取完整文件** —— 理解变更周围的完整上下文
2. **与主分支对比** —— 从 `$ARTIFACTS_DIR/.canonical-repo` 读取同一文件，查看前后差异
3. **评估修复**：
   - 它是否确实解决了主分支上发现的缺陷/漏洞？
   - 它是最简单的修复方案吗？（KISS 原则）
   - 它是否处理了边界情况？
   - 它是否会引入新缺陷？
   - 它是否遵循了代码库中的现有模式？
4. **检查 CLAUDE.md 合规性**：
   ```bash
   cat CLAUDE.md
   ```
   - 导入模式是否正确？
   - 类型注解是否完整？
   - 错误处理是否恰当？
   - 是否存在不必要的复杂性？

### 2.4 查找问题

检查以下方面：
- **正确性**：修复是否真正解决了问题？
- **完整性**：缺陷的所有方面是否都得到了处理？
- **副作用**：是否会破坏其他功能？
- **性能**：是否存在不必要的重渲染、高开销操作？
- **类型安全**：所有类型是否正确，是否存在未经充分论证的 `any`？
- **错误处理**：错误是否被捕获并妥善处理？
- **过度工程**：变更是否超出了必要范围？（YAGNI 原则）
- **遗漏变更**：是否有本应修改但未被修改的文件？

### 2.5 比较替代方案

思考是否存在更好的修复方式：
- 更简单的方案是否可行？
- 是否存在应使用的现有工具函数/模式？
- 如果在不同层级实施，修复方式是否会有所不同？
