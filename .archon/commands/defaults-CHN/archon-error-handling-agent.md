# 错误处理审查代理

---

## 你的任务

排查静默失败、不完善的错误处理、过于宽泛的 catch 块以及不当的回退行为。生成结构化的产物，包含发现的问题、带选项的修复建议及其理由。

**输出产物**: `$ARTIFACTS_DIR/review/error-handling-findings.md`

## 阶段 1: 加载 - 获取上下文

### 1.1 从注册文件获取 PR 编号

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number)
```

### 1.2 阅读审查范围

```bash

```

## 阶段 2: 分析 - 排查问题

### 2.1 查找所有错误处理代码

搜索以下模式:
- `try { ... } catch` 块
- `.catch(` 处理器
- `|| fallback` 模式
- `?? defaultValue` 模式
- `?.` 可选链（可能隐藏错误）
- 错误事件处理器
- 条件性错误状态处理

### 2.2 逐一审查每个处理器

对每一处错误处理代码，评估以下方面:

**日志质量:**
- 错误是否以适当的严重级别记录？
- 日志是否包含足够的上下文信息？
- 这些日志在 6 个月后是否有助于调试？

**用户反馈:**
- 用户是否收到了可操作的反馈？
- 错误信息是否具体且有帮助？
- 技术细节是否适当地隐藏或展示？

**catch 块的具体性:**
- 是否只捕获了预期的错误类型？
- 是否可能意外抑制了无关错误？
- 是否应该使用多个 catch 块？

**回退行为:**
- 回退行为是否有明确的文档说明或预期？
- 回退行为是否掩盖了根本问题？
- 用户是否意识到他们看到的是回退行为？

### 2.3 查找代码库中的错误处理模式

```bash
# 在代码库中查找错误处理模式
grep -r "catch" src/ --include="*.ts" -A 3 | head -30
grep -r "console.error" src/ --include="*.ts" -B 2 -A 2 | head -30
```

**阶段 2 检查点:**
- [ ] 所有错误处理器已识别
- [ ] 每个处理器已评估
- [ ] 代码库模式已发现
