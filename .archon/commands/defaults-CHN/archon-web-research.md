# 网络调研

**输入**：$ARGUMENTS
**工作流 ID**：$WORKFLOW_ID

---

## 任务目标

搜索网络以获取与当前 issue 或功能相关的信息。查找官方文档、已知问题、最佳实践和解决方案，为实现提供参考。

**输出**：`$ARTIFACTS_DIR/web-research.md`

**核心原则**：策略性搜索，优先权威来源，引用所有出处。

---

## 阶段 1：解析 - 理解调研目标

### 1.1 获取 Issue 上下文

如果输入看起来像 GitHub issue 编号：

```bash
gh issue view $ARGUMENTS --json title,body,labels
```

### 1.2 识别调研目标

从 issue 上下文中识别：

- 提及的关键技术、库或 API
- 需要搜索的错误消息或堆栈跟踪
- 需要澄清的概念或模式
- 特定版本的文档需求
- 生态系统中已有的基础设施 — 哪些内置或库级别的抽象已经解决了部分问题？（避免重复造轮子）

### 1.3 制定搜索计划

创建 3-5 个有针对性的搜索查询：

| 查询 | 目的 | 预期来源 |
|-------|-----|-----------------|
| "{库名} {功能} 文档" | 官方文档 | 库网站 |
| "{错误消息}" | 已知问题 | Stack Overflow、GitHub issues |
| "{模式} 最佳实践 {年份}" | 当前方案 | 博客文章、文档 |
| "{库名} 内置 {原语/功能}" | 避免重复造轮子 | 官方文档、更新日志、迁移指南 |

**阶段 1 检查点：**

- [ ] Issue 上下文已理解
- [ ] 调研目标已识别
- [ ] 搜索查询已制定

---

## 阶段 2：搜索 - 执行调研

### 2.1 检查 llms.txt

许多网站提供 LLM 优化的文档：

```
尝试获取 https://{domain}/llms.txt 以获取已知网站
阅读结果并获取其中链接的相关子页面
```

### 2.2 搜索官方文档

对于涉及的每项技术/库：

1. 在版本约束范围内搜索官方文档
2. 对已知权威来源使用 `site:` 操作符
3. 查找更新日志/发布说明以获取版本信息

### 2.3 搜索已知问题

如果 issue 涉及错误或缺陷：

1. 用引号包裹精确错误消息进行搜索
2. 检查相关库的 GitHub issues
3. 查找 Stack Overflow 上的回答

### 2.4 搜索最佳实践

如果 issue 涉及实现决策：

1. 搜索公认的模式和方案
2. 交叉验证多个来源
3. 如果要更换方案，查找迁移指南

**阶段 2 检查点：**

- [ ] 至少执行了 3 次搜索
- [ ] 找到了权威来源
- [ ] 提取了相关内容

---

## 阶段 3：综合 - 整理发现

### 3.1 按相关性组织

对于每个发现：

- **来源**：名称和 URL
- **权威性**：为什么这个来源可信
- **关键信息**：直接引用或具体事实
- **适用于**：与 issue 的哪个部分相关
- **版本/日期**：信息的时效性

### 3.2 识别冲突或空白

- 记录来源之间的矛盾信息
- 标注过时内容
- 记录未能找到的信息

**阶段 3 检查点：**

- [ ] 发现已整理
- [ ] 冲突已标注
- [ ] 空白已记录

## 质量标准

| 标准 | 要求 |
|----------|-------------|
| **准确性** | 逐字引用来源，提供直接链接 |
| **相关性** | 聚焦于直接解决 issue 的内容 |
| **时效性** | 注明发布日期和版本 |
| **权威性** | 优先使用官方文档、公认专家 |
| **完整性** | 从多个角度搜索，记录空白 |
| **透明性** | 标注过时、矛盾或不确定的信息 |

---

## 注意事项

- 能搜索时不要猜测
- 先检查搜索结果再获取页面
- 不要忽略技术内容的发布日期
- 不要将单一来源作为定论而不加佐证
- 不要跳过空白部分 — 对局限性保持诚实

---

- **ARTIFACT_WRITTEN**：调研结果已保存至 `$ARTIFACTS_DIR/web-research.md`
