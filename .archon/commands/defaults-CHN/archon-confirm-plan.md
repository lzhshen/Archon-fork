# 确认计划调研

**工作流 ID**: $WORKFLOW_ID

---

## 你的任务

在开始实施之前，验证计划的调研结果是否仍然有效。

计划可能会过时：
- 文件可能已被重命名或移动
- 代码模式可能已发生变更
- API 可能已更新

**本步骤不实施任何内容** -- 仅验证计划是否仍然准确。

---

## 阶段 1: 加载 -- 读取上下文制品

### 1.1 加载计划上下文

```bash
cat $ARTIFACTS_DIR/plan-context.md
```

如果未找到，停止并报错：
```
❌ 未在 $ARTIFACTS_DIR/plan-context.md 找到计划上下文

请先运行 archon-plan-setup。
```

### 1.2 提取验证目标

从上下文中识别：

1. **需要验证的模式** -- 需要验证的文件及行范围
2. **待变更文件** -- 将被创建/更新的文件
3. **验证命令** -- 应可正常执行的命令

**阶段 1 检查点:**

- [ ] 上下文制品已加载
- [ ] 待验证模式已提取
- [ ] 待变更文件已识别

---

## 阶段 2: 验证 -- 检查模式是否存在

### 2.1 验证模式文件

对于"需要验证的模式"中的每个文件：

1. 检查文件是否存在：
   ```bash
   test -f {file-path} && echo "EXISTS" || echo "MISSING"
   ```

2. 如果存在，读取引用的行：
   ```bash
   sed -n '{start},{end}p' {file-path}
   ```

3. 与计划的预期进行比较（如果计划包含代码片段）

### 2.2 记录发现

对于每个模式文件：

| 文件 | 状态 | 备注 |
|------|------|------|
| `src/adapters/telegram.ts` | ✅ 存在 | 第 11-23 行与预期模式匹配 |
| `src/types/index.ts` | ✅ 存在 | 接口仍然存在 |
| `src/old-file.ts` | ❌ 缺失 | 文件已被重命名/删除 |
| `src/changed.ts` | ⚠️ 已偏移 | 代码结构已显著变化 |

### 2.3 严重程度评估

| 发现 | 严重程度 | 处理方式 |
|------|----------|----------|
| 文件存在，代码匹配 | ✅ 正常 | 继续执行 |
| 文件存在，微小差异 | ⚠️ 警告 | 在制品中记录，谨慎继续 |
| 文件存在，严重偏移 | 🟠 需关注 | 标记供审查，可能需要更新计划 |
| 文件缺失 | ❌ 阻塞 | 停止，计划需要修订 |

**阶段 2 检查点:**

- [ ] 所有模式文件已检查
- [ ] 发现已记录
- [ ] 严重程度已评估

---

## 阶段 3: 验证 -- 检查目标位置

### 3.1 检查待创建文件

对于每个标记为 CREATE 的文件：

1. 验证其尚不存在（若存在则属于异常情况）：
   ```bash
   test -f {file-path} && echo "ALREADY EXISTS" || echo "OK - will create"
   ```

2. 验证父目录存在或可以创建：
   ```bash
   dirname {file-path} | xargs test -d && echo "DIR EXISTS" || echo "DIR WILL BE CREATED"
   ```

### 3.2 检查待更新文件

对于每个标记为 UPDATE 的文件：

1. 验证其存在：
   ```bash
   test -f {file-path} && echo "EXISTS" || echo "MISSING"
   ```

2. 如果计划引用了特定的行/函数，验证其是否存在

**阶段 3 检查点:**

- [ ] CREATE 目标已验证（尚不存在）
- [ ] UPDATE 目标已验证（已存在）
