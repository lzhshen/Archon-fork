# 测试覆盖率代理

---

## 任务目标

分析 PR 变更的测试覆盖率。识别关键缺陷，评估测试质量，确保测试验证的是行为（而非实现细节）。生成包含发现和建议的结构化产物。

**输出产物**：`$ARTIFACTS_DIR/review/test-coverage-findings.md`

---

## 阶段一：加载 -- 获取上下文

### 1.1 从注册文件获取 PR 编号

```bash
PR_NUMBER=$(cat $ARTIFACTS_DIR/.pr-number)
```

### 1.2 读取范围

```bash
cat $ARTIFACTS_DIR/review/scope.md
```

区分哪些文件是源文件，哪些是测试文件。

**重要提示**：检查是否存在"不构建（范围限制）"部分。其中列出的项目是**有意排除**的 -- 不要将其标记为缺陷或缺失测试覆盖！

### 1.3 获取 PR 差异

```bash
gh pr diff {number}
```

### 1.4 阅读现有测试

对每个新增/修改的源文件，找到对应的测试文件：

```bash
# 查找测试文件
find src -name "*.test.ts" -o -name "*.spec.ts" | head -20
```

**阶段一检查点：**
- [ ] 已识别 PR 编号
- [ ] 已识别源文件和测试文件
- [ ] 已记录现有测试模式

---

## 阶段二：分析 -- 评估覆盖率

### 2.1 源文件到测试的映射

对每个变更的源文件：
- 是否存在对应的测试文件？
- 新增函数/特性是否有测试？
- 修改函数的测试是否已更新？

### 2.2 识别关键缺陷

查找未测试的：
- 错误处理路径
- 边界情况（null、空值、边界值）
- 关键业务逻辑
- 安全敏感代码
- 异步/并发行为
- 集成点

### 2.3 评估测试质量

对现有测试，检查：
- 测试的是行为还是实现细节？
- 能否捕获有意义的回归问题？
- 对重构是否具有韧性？
- 是否遵循 DAMP 原则？
- 断言是否有意义？

### 2.4 查找测试模式

```bash
# 在代码库中查找测试模式
grep -r "describe\|it\|test\(" src/ --include="*.test.ts" | head -20
```

**阶段二检查点：**
- [ ] 源文件到测试的映射已完成
- [ ] 已识别关键缺陷
- [ ] 已评估测试质量
- [ ] 已找到代码库测试模式
